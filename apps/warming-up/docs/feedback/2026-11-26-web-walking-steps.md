# 홈 화면 웹앱의 산책 걸음 측정

아이폰 Safari에서 홈 화면에 추가한 밥뭇나와 갤럭시 웹앱에서 실제 산책을 측정하고, 하트 체험의 가상 걸음과 구별해 달라는 요청을 반영했다.

‘워밍이의 산책 → 내 걸음 측정 → 산책 측정 시작’에서 사용자가 동의하면 휴대폰 움직임을 읽는다. iOS에서 동작 접근 권한은 버튼을 누른 시점에 요청한다. 지원하는 브라우저는 가속도계를 쓰고, 동작 이벤트 경로에서는 중력 포함 가속도와 선형 가속도를 처리한다. 연속된 세 걸음에서 보행 리듬을 확인하면 첫 걸음부터 반영한다.

산책 시작 시각, 마지막 걸음 시각과 확인된 누적 걸음수를 산책별로 기기의 IndexedDB에 저장한다. 화면 숫자는 저장 성공 후 바뀐다. 앱 전환이나 화면 잠금 시 측정을 멈춘다. 신호를 얻지 못한 경우와 권한 거부 시에는 저장 기록을 만들지 않는다. 원시 가속도, 건강 앱의 하루 합계, 예시 하트 수치는 이 저장소에 넣지 않는다.

모바일 WebKit의 시험 센서 입력과 Chromium의 가상 가속도계에서 각각 10걸음을 표시했다. 산책을 마치고 브라우저를 재실행한 뒤에 같은 기록을 확인했다. 예시 걸음을 2,500으로 바꾼 뒤에도 측정 기록은 10걸음이었다.

영상으로 센 걸음수와 보행 구간을 모두 대조할 수 있는 공개 휴대폰 기록 117개에서 산책 한 회당 평균 절대 오차는 2.19걸음이었다. 휴대폰을 소지한 위치와 보행 패턴에 따라 오차가 달라진다. 참여자 본인의 아이폰·갤럭시에서 걸으면서 센 숫자와 직접 대조하는 확인은 남아 있다. [케임브리지대학교 보행 자료](https://doi.org/10.17863/CAM.12982)
