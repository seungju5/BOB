## B. 결정이 필요한 것

| # | 왜 바로 못 고쳤나 | 제안 |
|---|---|---|
| 1 | 삼성 로그인은 SmartThings 서버(OAuth)가 있어야 함. 지금 운영 사이트는 `server_not_deployed` 상태. 또 SmartThings OAuth는 "기기 읽기 권한 허용"이지 회원 로그인 수단이 아님 | 이메일 가입 → 바로 다음 단계에서 삼성 연결로 이어지게 하는 흐름 검토. 서버 배포는 피터 담당 |
| 2 | 안부 판정 기준 자체가 바뀜(알림 조건 변경). "휴대폰 사용(스크린타임)"은 지금 수집하는 데이터가 아님 → 새 데이터 수집 + 개인정보 안내 개정 필요 | 기준 확정 후 소개·기록·홈 색 범례를 한 번에 변경. 휴대폰 사용을 넣을지 먼저 결정 |
| 3 | **지금은 반영 안 됨.** 소개 4/5는 "필요할 때 소식을 남겨요. 매일 누르지 않아도 괜찮아요"까지만 있음. 다만 앱에 어르신 걸음 연결(헬스 커넥트 설치·권한) 화면이 있어서 "추가 행동 없음"이라고 쓰면 사실과 다를 수 있음 | 걸음 연결이 1회 설정이면 "처음 한 번 연결하면, 그다음엔 따로 하실 일이 없어요" 같은 문구 |
| 4 | **현재 로직과 이해가 다름.** 결식 알림은 "연속 N끼"라서 하루 3끼에 2끼면 하루가 안 됨(2일 아님). 이번 안내 문구는 현재 로직대로 씀 | "3끼면 2일"이 맞다면 기준을 끼니가 아니라 일수로 바꾸는 판단 로직 변경 필요 |
| 5 | 이번 주 리포트의 기간(오늘 포함 최근 7일 / 월~일)과 "평소"(지난 몇 주 평균인지) 정의 | 기간·평소 정의를 정하면 홈 카드 제목과 리포트 화면 함께 수정 |
| 6 | "700W 한 번만 찍혀도 취사"는 판단 기준값 변경(어제 ADR-014에서 15분으로 맞춤). 전기포트 등 순간 고전력과 구분이 어려워짐. 걸음 수 기록은 새 화면 기능 | 실측 근거와 함께 결정. 걸음 수는 2번(안부 기준)과 같이 결정 |
| 7 | 어르신 화면 원칙(버튼 3개, 확인 단계 한 번)과 충돌 가능 — 단계가 하나 늘어남 | 외식: 누르면 "오늘 점심 / 오늘 저녁 / 어제 저녁"처럼 최근 끼니 3개만 큰 버튼으로. 놀러가요: "오늘부터 / 내일부터" 두 개 추가 |
| 8 | 법적 문체 규정은 없음(이해하기 쉬운 표현이 오히려 권장). 다만 "~요"체는 약속의 무게가 가볍게 읽힐 수 있음 | 어르신 화면은 "~요"체 유지, 보호자용 전문 안내는 "~합니다"체로 바꾸는 안. 최종은 팀 결정 |
