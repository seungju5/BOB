# 한 가구에서 시작하는 밥솥 측정

첫 가구는 평소 쓰는 실물 플러그 한 대와 알림을 받을 휴대폰 한 대로 확인합니다. 한 번의 취사가 날짜별 기록과 그 휴대폰의 잠금화면까지 도착하면 둘째, 셋째 가구를 같은 방식으로 추가합니다.

## 운영 앱에서 측정과 푸시 대조

1. 본인 계정으로 로그인한 뒤 ‘우리 집 기기 연결 → 내 밥솥 연결 확인’을 엽니다. 직접 가져온 파일럿 실측은 원본의 최근 측정 분과 기록일을 표시합니다. 실물 플러그에서 웹훅 또는 정기 조회가 성공하면 ‘스마트싱스 자동 연결’에 측정 시각이 나타납니다.
2. 날짜를 눌러 당시 설정한 끼니 시간대와 취사 신호·추정 횟수를 확인합니다. 일별 화면에는 기록의 출처가 표시됩니다. 앱을 다시 조회해도 원본의 측정 시각은 그대로입니다.
3. 홈 화면에 설치한 앱에서 ‘이 휴대폰 알림 설정’을 엽니다. 팀 발송 서버와 이 기기의 등록이 준비된 경우 홈 화면 알림을 켤 수 있습니다. 실제 취사 푸시를 받으면 이 기기에 최근 24시간의 수신 시각과 해당 신호 시각이 표시됩니다. 시스템 알림을 누르면 누른 시각도 확인할 수 있습니다. 잠금화면 배너 표시는 수신자가 휴대폰을 잠근 상태에서 직접 확인합니다.

## 헤이홈 미니 플러그 연결

1. 헤이홈 앱에서 Mini를 등록하거나 이미 등록한 기기를 엽니다. 제조사는 Mini의 SmartThings 연동을 지원한다고 안내합니다. 밥솥에 연결할 때에는 제품과 밥솥의 정격 및 제조사의 고전력 기기 사용 안내도 확인합니다. [제조사 기기 안내](https://hej.life/article/%EC%83%81%ED%92%88-qa/6/109236/) · [사용 부하 안내](https://hej.life/article/%EC%83%81%ED%92%88-qa/6/92284/)
2. SmartThings의 기기 추가에서 제휴사 **Hejhome**을 선택해 같은 헤이홈 계정을 연결합니다. SmartThings에 들어온 플러그의 전력(W)과 최근 측정 시각을 확인합니다. 제조사 앱에서 이미 연결했다면 초기화할 필요가 없습니다.
3. 참여자 본인 계정의 공식 삼성 CLI에서도 새 측정을 확인할 수 있습니다. 밥뭇나 소스에서 `node scripts/export-personal-meter.mjs --only-smart-plug --fresh --out 개인점검.json`을 실행합니다. 실제 플러그가 여러 대면 `--only-smart-plug` 대신 `--device "표시 이름"`을 사용합니다. 새 W 측정이 있을 때만 로컬 파일을 남깁니다. 팀 DB와 자동 알림에 연결하는 단계는 아래를 따릅니다. [삼성의 제휴사 기기 형식](https://developer.smartthings.com/docs/devices/cloud-connected/interaction-types)

## 운영 개통과 현장 확인

| 순서 | 팀이 확인할 결과 |
| --- | --- |
| 팀 서버 | 삼성에서 팀 서비스의 시범 사용을 허용하고 등록한 콜백과 웹훅이 팀 HTTPS 서버에 도달합니다. 공개 설정의 `connectionReady`가 참이고 Web Push 공개키가 제공됩니다. 백그라운드 정기 조회와 보관 기한 정리 작업도 가동합니다. [서버 준비 절차](../../server/smartthings/README.md) |
| 가구 초대 | 팀 서버의 `SMARTTHINGS_PILOT_UIDS`에 동의한 가구의 Firebase UID만 등록합니다. 명단과 인증 정보는 공개 저장소에 쓰지 않습니다. 각 가구는 자기 밥뭇나 계정과 자기 삼성 계정으로 로그인해 자기 플러그를 선택합니다. |
| 새 신호 | 가구가 밥솥 취사 신호와 날짜별 기록을 켠 뒤 평소 취사에서 삼성 측정 시각과 밥뭇나 수신 시각을 대조합니다. 700W 이상 한 번이면 취사 신호 한 건입니다. 직전 기준 이상 측정과 10분 이내의 후속 측정은 한 건으로 묶습니다. |
| 날짜와 끼니 | 월별 기록에서 측정 날짜를 누릅니다. 설정한 1~5개 시간대 중 취사를 시작한 끼니가 표시됩니다. 시간대 밖이면 날짜별 취사 횟수에만 더합니다. 다른 가구에 같은 기록이 보이지 않는지도 확인합니다. |
| 잠금화면 | 알림 받을 휴대폰에서 밥뭇나 알림을 허용한 뒤 앱을 닫고 화면을 잠급니다. 시험 알림을 먼저 받은 뒤 평소 취사에서 자동으로 온 알림을 눌러 같은 날짜와 끼니가 열리는지 확인합니다. 아이폰은 iOS 16.4 이상에서 홈 화면에 추가한 웹앱으로 진행합니다. [Apple 안내](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/) |

휴대폰이 받았다는 증거는 잠금화면에서 관찰한 자동 알림과 그 알림으로 연 기록입니다. 팀원끼리는 익명 가구 번호와 단계별 통과 여부만 공유합니다. 이름·기기 ID·집별 생활 시각이나 원시 전력값을 저장소에 올리지 않습니다.

## 세 가구 운영 시 호출 수

가구당 플러그 한 대를 24시간 10분 간격으로 조회한다고 가정하면 전력 상태 조회는 한 가구 하루 144회, 두 가구 288회, 세 가구 432회입니다. 30일 기준 각각 4,320회, 8,640회, 12,960회입니다. 삼성 로그인·기기 목록·구독·토큰 갱신은 별도 요청이며, 실제 청구 조건은 삼성과 확인한 계약을 적용합니다.

## 파일럿 가구의 측정 자료 반영

가구가 제공에 동의한 실물 밥솥 플러그의 측정 한 건을 비공개 백엔드에서 가져올 수 있습니다. 이메일 인증을 마치고 계정 프로필과 가구 정보 이용 동의를 저장한 수신 계정 한 곳에 연결합니다. 운영자가 해당 가구의 기기와 수신 계정을 확인합니다. 고객은 평소처럼 **기록 → 날짜 → 밥솥 사용**에서 결과를 확인합니다.

팀 서버의 프로젝트 전용 Google 애플리케이션 기본 사용자 인증 정보를 사용합니다. 루트 패키지와 `server/smartthings` 의존성을 설치한 뒤 `npm run pilot:import -- /private/path/grant.json /private/path/source.png`를 실행합니다. 운영 원본과 승인 파일은 저장소·공개 폴더 밖에 두고 소유자만 읽도록 설정합니다. 승인 파일은 `projectId`, 이메일 인증이 끝난 `uid`와 `recipientEmail`, 해당 가구의 동의를 확인한 `consented`와 `physicalCooker`, 설정 문서의 `settingsRevision`(초:나노초), `format`(screenshot 또는 power-export), 입력 파일의 `sourceSha256`, 원본과 대조한 `measuredAt`(시간대 포함 ISO)와 `cooking`(기준 충족 여부)을 포함합니다. 수신 이메일이나 설정이 달라지면 기존 승인은 사용할 수 없습니다.

운영자가 받은 단일 공식 powerMeter 응답을 인수로 줄 때는 서버 메모리 안에서 이미지를 생성합니다. 기존 캡처도 같은 오프라인 한국어·영어 판독기로 판독합니다. 판독한 실제 측정 시각과 700W 판정이 원본과 일치할 때만 기록합니다. 그래프 평균이나 휴대폰 시계로 날짜를 추정하지 않습니다. 원본 이미지와 W는 Firebase에 저장하지 않습니다.

재입력은 합계를 늘리지 않습니다. 직전 기준 이상 신호로부터 10분 이내인 관측은 자정을 넘어가도 취사 한 건입니다. 원래 측정 날짜의 취사 횟수와 확인된 끼니 시간대만 일반 앱으로 전달합니다. 35일을 넘은 기록은 조회 시 정리하고 가구 동의를 철회하면 요약과 중복 확인 자료를 삭제합니다. 이전 형식의 기록도 계속 읽을 수 있습니다. 같은 날짜의 정식 삼성 자동 집계가 도착하면 그 집계를 우선합니다.

이 경로는 가구가 제공한 과거 측정의 반영에 사용합니다. 지속적인 자동 수집과 실시간 푸시는 정식 기기 연결과 각각의 사용자 동의가 필요합니다.

### 700W보다 낮은 취사 패턴

동의받은 실물 플러그 한 대의 측정 이력이 있으면 백엔드에서 날짜별로 그 밥솥의 평소 전력 범위를 계산합니다. 한국시간 기준 하루에 700W 미만 표본이 12개 이상 있어야 비교합니다. 평소 상위 전력대와 변동 폭을 넘어 올라온 뒤 앞뒤에서 다시 낮아진 구간을 찾습니다. 두 번 이상 이어진 상승, 또는 하루 중 특히 뚜렷한 단일 봉우리만 **취사 추정**으로 표시합니다. 측정 간격이 너무 멀거나 앞뒤가 비어 있으면 추정을 보류합니다. 반복 보온, 재가열과 취사를 전력만으로 완전히 구별하기 어려워 실제 취사 시각과 대조해 보정할 파일럿 기준입니다.

백엔드 입력 형식 `power-history`는 측정 시각(UTC epoch 밀리초)과 순간 전력(W)을 담은 `[{ "at": …, "watts": … }]`입니다. 기기·가구와 승인된 수신 계정, 원본 해시, 설정 버전을 확인한 뒤 처리합니다. 공식 삼성 SDK 클라이언트의 `readMeterHistory` 어댑터는 선택된 실물 콘센트 한 대에서 최대 7일을 읽고 마지막 이벤트의 시각과 해시로 다음 페이지를 요청합니다. 원본 전력은 메모리에서 처리합니다. 한 번의 화면 캡처에 찍힌 낮은 값으로 봉우리를 만들 수 없습니다.

10분 안에 이어진 봉우리는 한 구간으로 묶습니다. 같은 구간에 700W 이상 표본이 있으면 기존 기준 신호 한 건으로 표시합니다. 추정은 시작 시각이 속한 날짜와 저장된 가구의 끼니 시간대에 배정하고, 시간대 밖의 신호는 해당 날짜의 밥솥 사용에만 합산합니다. 원시 시각이나 W는 보호자 화면에 표시하지 않습니다. 추정 횟수는 확인율·결식 경보·과거 기록 푸시에 가산하지 않습니다. 새로운 이력으로 재분석할 때 기존 요약을 갱신하며, 같은 이력을 다시 읽어도 건수가 늘지 않습니다.
