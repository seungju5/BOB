# 보호자 홈과 소개, 삼성 계정 로그인 준비

소개에서 눌러 본 날짜를 보호자 홈에서도 같은 방식으로 열 수 있다. 홈은 한국 시간으로 이번 주 월요일부터 일요일까지를 보여 준다. ‘오늘’ 버튼으로 오늘 소식에 돌아온다. 첫 화면은 오늘이고, 요일을 누르면 끼니 시간대와 해당 날짜의 상세 기록 링크가 바뀐다. 각 날짜에 저장된 시간표를 사용한다. 외식이 확인 수에 들어가면 포함한 횟수를 적는다. 외출, 추정, 자료가 없는 날, 미래의 예정 시간대를 구분한다. 운영 홈에서는 해당 가구가 동의해 저장한 기록을 읽는다. 예시 요일 자료는 소개 전용이다.

소개 다섯 장은 같은 좌우 여백과 노란 머리 영역을 사용한다. 본문 카드는 내용만큼 자라고 다음 버튼은 카드 아래에 있다. 어르신 소식 예시는 어르신 홈과 같은 세로 순서와 그림 기호를 보여 준다.

## 삼성 계정을 발급받은 후 운영에 여는 순서

현재 팀이 확인한 삼성 계정 로그인용 웹 클라이언트는 발급 전이다. 운영 Firebase에는 이메일 로그인이 열려 있다. 보호자는 기존 이메일로 가입·로그인하고, 기기 연결은 로그인 후 별도로 동의한다.

1. 팀 명의 삼성 로그인용 웹 클라이언트를 발급받고 지원하는 OIDC 발급자와 발견 문서, 이메일 범위, ID 토큰 서명 및 검증된 이메일 제공 여부를 확인한다. 삼성에 등록할 Firebase 콜백은 `https://warming-up-bapmunna.firebaseapp.com/__/auth/handler`이다. [삼성 계정 개발자 콘솔](https://developer.account.samsung.com/intro)
2. 팀 Firebase에서 Identity Platform 설정을 검토하고 OIDC 공급자 `oidc.samsung`을 authorization code 흐름으로 등록한다. 클라이언트 시크릿은 인증 공급자의 비밀 설정에 넣는다. Spark에서 SAML/OIDC는 24시간 동안 고유 사용자 2명 한도이다. 세 가구 이상의 베타 운영은 실제 로그인할 사람 수로 한도를 산정한다. [Firebase OIDC 연결](https://firebase.google.com/docs/auth/web/openid-connect) · [Firebase 요금제별 인증 한도](https://firebase.google.com/docs/auth#limits)
3. 검증 환경에서 새 삼성 로그인과 기존 이메일 계정의 ‘내 계정 → 삼성 계정 연결하기’를 각각 시험한다. 기존 계정 연결 전후에 사용자 ID와 같은 가구의 기록이 일치하는지, 인증 취소와 팝업 차단 시 이메일 로그인이 가능한지 휴대폰에서 확인한다. 이메일 확인이 필요하면 밥뭇나의 이메일 인증을 마친다.
4. 시험을 통과한 설정으로 팀의 `config/team.ts`에서 `TEAM_SAMSUNG_SIGN_IN_ENABLED`를 켜고 배포한다. 다시 끄면 이메일 로그인으로 운영할 수 있다. 기기 읽기 권한이나 SmartThings용 앱 ID는 계정 로그인에 쓰지 않는다.
