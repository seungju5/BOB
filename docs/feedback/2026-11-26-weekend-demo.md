# 밥뭇나 주말 시연 · 플러그 조회와 걸음수

11월 29일(일)까지 팀원이 발표용 플러그 한 대의 측정 결과를 밥뭇나에서 확인하고, 휴대폰으로 직접 걸어 측정과 저장을 확인한다. 팀은 실물 점검을 11월 28~29일에 함께 진행하기로 했다.

## 발표 컴퓨터에서 플러그 확인

1. 밥솥 플러그가 등록된 계정의 소유자가 SmartThings 앱에서 플러그와 마지막 측정 시각을 확인한다. 시연 당일 삼성 토큰 페이지에서 **Generate new token**을 누르고 기기 읽기 권한(`r:devices:*`)을 선택한다. 새 개인 액세스 토큰(PAT)은 발급 후 24시간 동안 유효하다. [삼성 토큰 발급](https://account.smartthings.com/tokens) · [삼성 권한 안내](https://developer.smartthings.com/docs/getting-started/authorization-and-permissions)
2. 발표 컴퓨터에서 아래 명령을 실행한다. 기존 개발 폴더는 `warming-up`이다. 처음 복원한 폴더에서는 Node.js 24와 `npm ci`로 의존성을 준비한다.

   ```sh
   npm run build
   npm run demo:smartthings
   ```

3. 터미널에 표시된 주소를 열고, 화면 공유를 시작하기 전에 소유자가 가려진 입력란에 PAT를 붙여 넣는다. **기기 목록 불러오기**에서 시연에 동의한 플러그를 선택한다. 여러 콘센트가 있는 기기는 밥솥을 꽂은 콘센트를 고른다. [발표 컴퓨터에서 시연 열기](http://127.0.0.1:4317/connect/demo/)
4. **측정 결과 한 번 조회**를 누른다. 화면에서 기기 유형, 삼성의 마지막 측정 시각, 밥뭇나의 조회 시각과 취사 기준 해당 여부를 확인한다. 삼성 앱과 같은 측정 시각을 대조한다. 기기가 측정값을 보내지 않았거나 이전 측정만 있는 경우에는 화면에 나온 상태를 그대로 기록한다.
5. 시연을 마치면 **결과 닫기**를 누르고 터미널에서 `Ctrl+C`로 서버를 종료한다. 계정 소유자는 삼성 발급 화면에서 사용한 PAT를 폐기할 수 있다.

기기 목록을 받아오면 밥뭇나가 발표 컴퓨터의 메모리에 10분 유효한 조회권을 만든다. 선택한 콘센트 상태를 삼성에 한 번 요청하면 조회권은 사용 처리된다. 삼성 요청이 실패해도 다음 시도는 **기기 목록 불러오기**부터 시작한다. 계정 토큰과 원시 전력값은 파일이나 가구 기록에 저장하지 않는다. 이 시연으로 확인하는 범위는 삼성 API 호출과 화면 표시다. 정식 가구별 로그인과 동의는 후속 연동 범위다. [삼성 기기 조회 방식](https://developer.smartthings.com/docs/service-integrations/query-and-list-devices)

## 휴대폰으로 걸음수 확인

1. 시연할 휴대폰의 Safari 또는 Chrome에서 **내 걸음 측정**을 열고 **산책 측정 시작**을 누른다. 동작 접근 요청이 뜨면 허용한다. [휴대폰 걸음 측정](https://warming-up-bapmunna.web.app/walking/steps/)
2. 측정 화면을 켠 채 휴대폰을 손에 들고 10초간 가만히 선다. 이어서 팀원 한 명이 세어 주는 동안 평소 속도로 30걸음을 걷고, 앱에 표시된 수를 기록한다. 아직 센서 신호가 들어오지 않은 상태는 화면에 대시로 표시된다.
3. **산책 마치기**를 누른 뒤 페이지를 새로 열어 같은 기록이 **내 산책 기록**에 남아 있는지 본다. 화면을 잠그거나 다른 앱으로 가면 그 시점에 측정이 멈춘다.

| 팀 현장 점검 | 기록 |
| --- | --- |
| 실물 플러그 유형, 앱과 삼성의 마지막 측정 시각 일치 여부 | 주말 확인 예정 |
| 조회 결과가 최근 측정인지, 이전 측정인지, 측정값이 없는지 | 주말 확인 예정 |
| 휴대폰 기종·브라우저, 정지 10초 후 표시 | 주말 확인 예정 |
| 직접 센 30걸음 / 앱 표시 / 다시 열어 본 기록 | 30 / ___ / ___ |

## 멘토님께 드릴 메시지 초안

멘토님 안녕하세요. 고려대학교 워밍업 팀입니다. 밥뭇나에서 밥솥 스마트플러그의 마지막 측정 결과를 조회하는 기능과, 휴대폰을 들고 걷는 동안 걸음수를 측정하고 저장하는 기능을 구현했습니다. 주말에는 팀 플러그와 휴대폰으로 두 기능을 시연하고 위 표에 결과를 기록할 예정입니다.

시연을 보시고 두 가지에 대해 의견을 부탁드립니다. 먼저, 삼성 앱과 밥뭇나의 측정 시각을 대조한 뒤 정식 가구별 로그인 연동으로 넘어가도 될지, 이 단계에서 더 확인해야 할 상황이 있을지 궁금합니다. 걸음수는 사람이 센 수와 앱의 표시를 비교하려고 합니다. 파일럿 전에 어느 정도의 오차를 허용하고 어떤 조건에서 반복해 보면 좋을지도 조언 부탁드립니다. 시간 내주셔서 감사합니다.

## 11월 26일 확인한 결과

- 공식 API와 같은 형식의 시험 응답으로 목록 조회부터 화면 표시까지 브라우저에서 확인했다. 동일 조회권을 재사용하면 HTTP 410이 반환됐고, 삼성 상태 조회를 대신한 시험 서버는 한 번만 호출됐다. 이전 측정 안내와 두 시각도 확인했다.
- Chromium 가상 가속도계로 정지 중 0걸음, 10걸음 입력 후 화면과 재접속 기록 모두 10걸음을 확인했다. 팀원이 실제로 걸은 결과는 위 표에 따로 기록한다.
- 앱 단위 검사 377개와 로컬 Firestore 에뮬레이터를 사용한 SmartThings 서버 검사 119개가 모두 통과했다. 서버 검사에는 이번 시연 API의 단회 사용·권한·실패 처리 검사 7개가 포함된다.
