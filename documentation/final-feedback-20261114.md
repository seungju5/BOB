## 계정·저장 경계

공개 `/bapmunna/app/`은 기존 `ku-gpa` Firebase 인증을 사용하며, Supabase 설치가 필요 없다. 기존 Firebase SDK와 명명된 앱 인스턴스를 재사용한다. 기존 `/carer`와 공유 진입점의 일반 보호자 흐름은 전체 앱으로 연결하고, OAuth 반환·개인정보·별도 체험 경로는 유지한다. 기존 BOB Supabase와 Firebase의 계정·데이터는 합치지 않는다.

실제 저장은 본인 전용 가구 문서와 새 `preferences/settings` 문서로 제한한다. 확인된 이메일·일치 UID·서버 읽기 결과를 요구한다. 입력 항목·시간 범위·서버 시각을 Rules에서도 검증한다. 다른 탭의 최신 수정은 revision 비교로 보호하며, 충돌 시 입력 초안을 남겨 다시 확인하게 한다. 온보딩을 완료한 계정은 소개를 다시 보더라도 미완료 상태로 되돌리지 않는다.

로그인 자동 이동은 완료한 인증 작업이 돌려준 UID와 현재 계정이 일치할 때만 허용한다. 세션 복원만으로 이동하지 않고, 계정 변경·새 작업·오류·데모 선택은 이전 이동 의도를 지운다. 타임아웃 뒤 도착한 로그인 결과가 다음 계정의 진행을 가로채지 않도록 검증한다.

## 실제 운영에서 아직 완료하지 않은 항목

1. **카카오 로그인·Identity Platform 전환은 사용자 결정대로 보류.** 과금은 켜지 않는다.
2. SmartThings 공개 서버는 별도 채팅에서 준비 중이다. 이번 화면은 연결 안내를 제공하고 원점이 검증되기 전까지 자동 신호 수신을 시작하지 않는다. 기존 CLI 기기 읽기는 웹 OAuth·웹훅 성공의 증거가 아니다.
3. 실제 가족 휴대폰 페어링·기기 신호 기반 식사 기록·외부 알림 발송을 이번 Firebase 전체 앱에서 완료했다고 표시하지 않는다. 계정 설정 저장과 가족 공유 동의는 별개다.
4. 실제 Google 계정의 새 OAuth 동의 완료, 실사용 기기의 네이티브 건강 권한, APK/IPA 서명·설치, 건강 데이터 수신은 이번 로컬 검사에 포함하지 않는다.
5. 실제 카카오·iMessage 수신 카드, OS 200% 글꼴·모션 설정을 바꾼 실기기 검증은 미수행이다. CSS의 모션 줄이기 대응과 키보드 확인을 별도 기록한다.
6. 네 번째 끼니 Supabase SQL·Edge 변경은 소스만 포함하며 BOB 운영 DB/함수에 적용하지 않는다.

운영 Firestore 변경은 새 본인 설정 경로를 추가한 밥뭇나 namespace만 교체하고 기존 KU GPA·다른 앱 규칙을 보존한다. Hosting은 현재 공개 전체 파일맵을 기준으로 `/bapmunna/` 변경분만 겹쳐 게시하며 기존 경로·설정·과금 상태를 검증한다.
