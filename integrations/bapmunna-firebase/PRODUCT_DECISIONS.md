# 밥뭇나 제품 결정 기록

사용자가 대화에서 정한 지속적인 제품 방향입니다. 과거 탐색안은 보관하되 이후의 명시적 선택을 우선합니다. 이 기록은 모든 과거 산출물의 완료를 뜻하지 않습니다.

## 현재 유지할 정체성

- 서비스명은 **밥뭇나**, 부제는 **밥 한 끼로 전하는 안부**.
- 노란색·크림·따뜻한 갈색을 중심으로 한다. 무지개 색 실험은 중단한다.
- Firebase의 ‘밥뭇나’ 글자 로고와 토끼를 보존한다. 2026-11-03 최신 선택에 따라 초록 가디건 3D 토끼 원본(`bunny.png`)을 전 화면의 동반 캐릭터로, 노란 `rice-logo.png`를 브랜드 심볼로 사용한다.
- 2026-11-03의 최종 사용자 선택에 따라 처음 만든 입체감 있는 3D 토끼 원본을 사용한다. 초록 가디건·클립보드·접힌 귀·둥근 눈의 정체성을 그대로 보존한다. 손그림 변형(`bunny-natural.png`)은 제작 이력으로만 남긴다. 시작 화면의 가벼운 점프·하트는 접근성을 해치지 않게 한다.
- Supabase의 밥 캐릭터를 참고한 작은 동반 캐릭터를 사용할 수 있지만 기존 토끼를 대체하지 않는다.
- 2026-10-17의 크림색 밥솥·웃는 밥 캐릭터 적용은 이전 선택으로 보존한다. 11월 3일의 토끼·노란 밥솥 선택이 우선하며, 시작·역할별 홈·1분 체험·계정·관리 화면의 로고와 브라우저 아이콘을 일치시킨다. 장식 캐릭터는 데이터로 달라지는 안부 밥그릇을 대체하지 않는다.
- 신이어마켙 협업 표시는 기존 승인 시안을 유지한다. 로고·말풍선의 손글씨 느낌은 살리되 제공된 폰트 파일 없이 원본 서체를 100% 복제했다고 주장하지 않는다.
- 말풍선 문구는 **토끼처럼 부지런하면 무엇이든 해내겠지요**. 사용할 때 캐릭터와 자연스럽게 연결하고 일반 정보 글자의 가독성과 구분한다.

## 화면과 조작

- 초기 서비스 방향은 A의 반가운 시작, C의 큰 글씨·명확한 조작, B의 따뜻한 밥그릇 그림을 결합한다.
- 시니어는 **외식했어요 / 놀러가요 / 도움 요청(도와줘요)** 세 가지 주요 행동에 집중한다. 일상적으로 눌러야 하는 “밥 먹었어요”나 “밥 사진 남기기” 슬롯은 다시 넣지 않는다. 사진 버튼에 대한 초기 요청은 이후의 최소 조작 결정으로 대체됐다.
- 보호자는 오늘의 안부, 마지막 기기 소식, 기록·리포트·알림을 빠르게 읽을 수 있어야 한다. 더보기는 항목별 목적이 명확하고 깊지 않게 구성한다.
- 누구나 어르신용·보호자용 화면을 전환할 수 있다. 전환 자체로 타인의 데이터 접근 권한이 생기면 안 된다.
- 밥그릇 양의 변화는 밥솥 사용·확인 데이터에 연결하되 실제 식사량이나 건강을 의미하지 않는다.
- 시니어 글자·대비·터치 영역을 우선하며 여백과 둥근 선택창으로 단순하지만 단조롭지 않게 한다. 세 가지 비교 시안을 다시 만들 경우 구조와 표현의 차이를 분명히 한다.
- 처음 보는 사람은 1분 안부 체험으로 신호에서 가족의 확인까지 이해할 수 있게 한다. 이 체험은 현재 기록을 바꾸지 않는 독립된 가상 상태로 실행한다.
- 기록의 근거를 눌러 확인할 수 있게 한다. 기기에서 온 소식·직접 남긴 외식 소식·연결 문제를 섞지 않고, 도움 요청의 읽음은 연락 완료와 구분한다.

## 소개 영상

- 기존 토끼의 가벼운 점프, 노란색·크림 배경, 실제 앱 캡처를 사용한다. 영상용 가짜 기능 화면을 만들어 실서비스로 소개하지 않는다.
- 질문에서 시작해 어르신의 최소 행동과 보호자의 안부 확인으로 이어지는 약 1분 구성으로 한다. 한국어 내레이션과 자막을 함께 제공한다.
- 합성 음성임을 산출물에 기록한다. 시제품의 현재 범위와 남은 센서·가족 연동 검증을 명시하고, 건강 진단·자동 신고·실제 전화 연결을 약속하지 않는다.

## 기능과 운영

- 기능정의서 v1.1과 루트 Supabase 구현을 기준으로 정합성을 검토한다. 사용자는 취사·열림의 끼니 확인, 마지막 활동 이후 48·72시간 등 판단 규칙도 Supabase와 같게 하도록 승인했다.
- 우선 센서 시뮬레이터로 검증한다. 실제 기기 연동이나 자동 긴급 신고를 구현한 것처럼 보이지 않게 한다.
- 서비스 운영 주소는 Impact Series의 밥뭇나이며 Gyeongju Ro/KU Open World와 분리한다. 운영 변경은 별도 배포 검증을 거친다.
- `seungju5/-1`의 기존 Next.js/Supabase 앱을 유지하고 Firebase 코드는 별도 폴더·PR로 추가한다. 기능은 맞추고 시각 디자인은 Firebase 것을 유지한다.
- 자동화된 판단 코드 정합성 검사와 사람의 화면·API 검토를 함께 사용한다. 계정·DB·사용자 데이터는 임의로 이전하거나 합치지 않는다.

## Supabase 변경마다 확인할 목록

1. 판단·기준값 변경: 공통 원본 갱신, `sync:firebase`, 경계값·동등성 테스트.
2. 기능 변경: Firebase 대응 화면과 상태·오류·접근성 검토. 반영하지 못하면 차이를 README에 명시.
3. 데이터·인증 변경: 별도 어댑터와 권한 검토. 자동 복사·운영 배포 금지.
4. 시각 회귀: 선택된 밥솥 심볼과 기존 글자 로고, 원본 3D 토끼, 노란색, 세 버튼, 모바일 역할 전환 확인.
5. 결과: 테스트·차이·배포 여부를 PR과 log.md에 기록.

## 별도 산출물 이력

기업 조사 보고서, PRD·페르소나, 녹취 PDF, 토끼 실리콘 센서 피규어 예상도, Figma 3종 시안은 대화에서 요청된 별도 작업이다. 이 통합 PR이 해당 산출물의 생성·완료를 증명하지 않으며, 다시 요청되면 기존 파일과 상태를 먼저 확인한다. 자이로 피규어는 확장 검토용이며 실측 없이 핵심 센서로 확정하지 않는다.

## 2026-11-03 로그인·기기 연결

- 최신 사용자 선택은 처음 만든 초록 가디건 3D 토끼 원본을 시작·로그인·연결·기기 소식에 일관되게 사용하는 것이다. 노란 밥솥은 브랜드 로고로 유지한다. 토끼 표정은 건강/식사 판정을 뜻하지 않는다.
- 본인 Firebase 로그인 후 삼성 OAuth 동의, 전력 측정 플러그 1개 선택, 신호 도착 확인, 재연결과 해제를 구현한다. 실제 연결을 가상 가족 요약·식사 판정에 자동 합치지 않는다.
- 앱 권한은 `r:devices:*` 읽기만 요청한다. 브라우저는 토큰·원시 전력·다른 가구 데이터에 접근하지 않는다.
- Impact Series의 `/api/smartthings/callback`, `/api/smartthings/events`와 읽기 권한을 삼성 OAuth 앱에 등록하고 API로 재조회했다. 공개 서버는 미배포, Target URL은 `PENDING`이다. 실제 사용자 인증·기기 구독·자동 신호 수신을 별도 완료 증거로 기록한다.
- 기존 기본 Firestore의 서울 리전과 같은 `asia-northeast3`에 요청 기반 Cloud Run을 준비한다. 최소 0·최대 1 인스턴스, 1 vCPU·512 MiB·60초 요청 제한을 계획하며 결제 연결은 사용자 결정 후 진행한다. 예산 알림은 요금 상한이 아니다.
- 팀 시연은 본인 계정 연결 → 플러그 선택 → 실제 신호 도착의 화면과 시각으로 입증한다. 합성 체험·Figma·단위 테스트를 실제 연결 성공 증거로 사용하지 않는다.
- 후속 사용자 결정: “유료 전환 없이 현재 등록·구현 상태 유지”. Spark를 유지하며 결제 연결·유료 서비스 활성화·공개 API 배포는 진행하지 않는다. 실제 OAuth·자동 수신 시연은 보류하고 현재 구현 화면과 등록 결과까지만 공유한다. 사용자가 재개하기 전 결제 승인을 반복 요청하지 않는다.
- 11월 4일 신규/수정 제한과 12월 15일 미가입 API 제한 가능성을 공식 공지에서 확인했다. 오늘의 등록과 이후 유료 플랜 이용 조건은 별개다.

## 2026-11-03 승인 디자인 공통 반영

최신 사용자 요청에 따라 Firebase 통합판의 승인된 토끼·로고·색상·서체를 루트 Next.js/Supabase 표시 계층에도 공유한다. `scripts/sync-design.mjs`로 자산을 생성·검사한다. 기능·데이터 어댑터와 권한은 그대로 유지하며, 정적 공개 앱과 Figma 가이드를 갱신한다. 공개 API 서버·과금 보류 결정은 유지한다.

## 2026-11-03 토끼 자체의 환영 동작

기존 큰·작은 점프를 유지하면서 다리 접기·귀 움직임·손 흔들기·눈 깜빡임·고개 인사를 16자세, 3.6초의 프레임 애니메이션으로 연결한다. 무한 반복하지 않으며 모션 줄이기·다시 보기·원본 대체 이미지를 제공한다. 원본 토끼는 다른 화면에 유지한다. 자세한 자산·접근성 결정은 [동작 기록](documentation/bunny-greeting.md)에 둔다.

## 2026-11-04 원본 그래픽 일치 우선

사용자는 이전 승인 원본과 완전히 같은 그래픽을 요청했다. 생성된 16자세 토끼 대신 `bunny.png`의 픽셀을 그대로 쓰는 2.5D 관절 변형으로 전환한다. 두 번의 점프·가벼운 손 인사·깜빡임·고개 인사는 유지하고 부드러운 착지 그림자를 더한다. 원본 자산은 변경하지 않으며 정지하면 원본 이미지로 돌아온다. 자세·전후면이 있는 새 3D 모델로 설명하지 않는다.

## 2026-11-04 손 인사 왜곡 제거

사용자가 지적한 얼굴·손 일그러짐을 해결한다. 피부 메시와 눈 압축을 제거하고 얼굴과 손을 독립적으로 표시한다. 손·연필에는 같은 회전·이동만 적용하며 비균일 변형을 금지한다. 이전 원본을 유지하고, 새 이미지는 손 뒤에 가려졌던 옷·털 복원 영역에만 사용한다. 두 번의 점프는 유지한다.
