# 밥뭇나 제품 결정 기록

사용자가 대화에서 정한 지속적인 제품 방향입니다. 과거 탐색안은 보관하되 이후의 명시적 선택을 우선합니다. 이 기록은 모든 과거 산출물의 완료를 뜻하지 않습니다.

## 현재 유지할 정체성

- 서비스명은 **밥뭇나**, 부제는 **밥 한 끼로 전하는 안부**.
- 노란색·크림·따뜻한 갈색을 중심으로 한다. 무지개 색 실험은 중단한다.
- Firebase의 로고와 토끼를 보존한다. 밥이 소복한 밥솥 상징이 기억에 남도록 한다.
- 토끼는 부드럽고 자연스러운 자세·절제된 표정·손그림 질감으로 다듬는다. 과도한 광택, 인형 같은 비례 과장, 장식 과잉을 피한다. 시작 화면의 가벼운 점프·하트는 접근성을 해치지 않게 한다.
- Supabase의 밥 캐릭터를 참고한 작은 동반 캐릭터를 사용할 수 있지만 기존 토끼를 대체하지 않는다.
- 2026-10-17에 사용자가 제공한 **뚜껑이 열린 크림색 밥솥·웃는 밥 캐릭터**를 기기 소식의 동반 캐릭터로 사용한다. 시니어 소식 행·보호자 카드 제목·센서 체험에만 절제해서 배치한다. 캐릭터의 가득한 밥은 장식이며 데이터로 달라지는 안부 밥그릇을 대체하지 않는다.
- 신이어마켙 협업 표시는 기존 승인 시안을 유지한다. 로고·말풍선의 손글씨 느낌은 살리되 제공된 폰트 파일 없이 원본 서체를 100% 복제했다고 주장하지 않는다.
- 말풍선 문구는 **토끼처럼 부지런하면 무엇이든 해내겠지요**. 사용할 때 캐릭터와 자연스럽게 연결하고 일반 정보 글자의 가독성과 구분한다.

## 화면과 조작

- 초기 서비스 방향은 A의 반가운 시작, C의 큰 글씨·명확한 조작, B의 따뜻한 밥그릇 그림을 결합한다.
- 시니어는 **외식했어요 / 놀러가요 / 도움 요청(도와줘요)** 세 가지 주요 행동에 집중한다. 일상적으로 눌러야 하는 “밥 먹었어요”나 “밥 사진 남기기” 슬롯은 다시 넣지 않는다. 사진 버튼에 대한 초기 요청은 이후의 최소 조작 결정으로 대체됐다.
- 보호자는 오늘의 안부, 마지막 기기 소식, 기록·리포트·알림을 빠르게 읽을 수 있어야 한다. 더보기는 항목별 목적이 명확하고 깊지 않게 구성한다.
- 누구나 어르신용·보호자용 화면을 전환할 수 있다. 전환 자체로 타인의 데이터 접근 권한이 생기면 안 된다.
- 밥그릇 양의 변화는 밥솥 사용·확인 데이터에 연결하되 실제 식사량이나 건강을 의미하지 않는다.
- 시니어 글자·대비·터치 영역을 우선하며 여백과 둥근 선택창으로 단순하지만 단조롭지 않게 한다. 세 가지 비교 시안을 다시 만들 경우 구조와 표현의 차이를 분명히 한다.
- 처음 보는 사람은 1분 안부 체험으로 신호에서 가족의 확인까지 이해할 수 있게 한다. 이 체험은 현재 기록을 바꾸지 않는 독립된 가상 상태로 실행한다.
- 기록의 근거를 눌러 확인할 수 있게 한다. 기기에서 온 소식·직접 남긴 외식 소식·연결 문제를 섞지 않고, 도움 요청의 읽음은 연락 완료와 구분한다.

## 소개 영상

- 기존 토끼의 가벼운 점프, 노란색·크림 배경, 실제 앱 캡처를 사용한다. 영상용 가짜 기능 화면을 만들어 실서비스로 소개하지 않는다.
- 질문에서 시작해 어르신의 최소 행동과 보호자의 안부 확인으로 이어지는 약 1분 구성으로 한다. 한국어 내레이션과 자막을 함께 제공한다.
- 합성 음성임을 산출물에 기록한다. 시제품의 현재 범위와 남은 센서·가족 연동 검증을 명시하고, 건강 진단·자동 신고·실제 전화 연결을 약속하지 않는다.

## 기능과 운영

- 기능정의서 v1.1과 루트 Supabase 구현을 기준으로 정합성을 검토한다. 사용자는 취사·열림의 끼니 확인, 마지막 활동 이후 48·72시간 등 판단 규칙도 Supabase와 같게 하도록 승인했다.
- 우선 센서 시뮬레이터로 검증한다. 실제 기기 연동이나 자동 긴급 신고를 구현한 것처럼 보이지 않게 한다.
- 서비스 운영 주소는 Impact Series의 밥뭇나이며 Gyeongju Ro/KU Open World와 분리한다. 운영 변경은 별도 배포 검증을 거친다.
- `seungju5/-1`의 기존 Next.js/Supabase 앱을 유지하고 Firebase 코드는 별도 폴더·PR로 추가한다. 기능은 맞추고 시각 디자인은 Firebase 것을 유지한다.
- 자동화된 판단 코드 정합성 검사와 사람의 화면·API 검토를 함께 사용한다. 계정·DB·사용자 데이터는 임의로 이전하거나 합치지 않는다.

## Supabase 변경마다 확인할 목록

1. 판단·기준값 변경: 공통 원본 갱신, `sync:firebase`, 경계값·동등성 테스트.
2. 기능 변경: Firebase 대응 화면과 상태·오류·접근성 검토. 반영하지 못하면 차이를 README에 명시.
3. 데이터·인증 변경: 별도 어댑터와 권한 검토. 자동 복사·운영 배포 금지.
4. 시각 회귀: 기존 로고, 자연스러운 토끼, 노란색, 세 버튼, 모바일 역할 전환 확인.
5. 결과: 테스트·차이·배포 여부를 PR과 log.md에 기록.

## 별도 산출물 이력

기업 조사 보고서, PRD·페르소나, 녹취 PDF, 토끼 실리콘 센서 피규어 예상도, Figma 3종 시안은 대화에서 요청된 별도 작업이다. 이 통합 PR이 해당 산출물의 생성·완료를 증명하지 않으며, 다시 요청되면 기존 파일과 상태를 먼저 확인한다. 자이로 피규어는 확장 검토용이며 실측 없이 핵심 센서로 확정하지 않는다.
