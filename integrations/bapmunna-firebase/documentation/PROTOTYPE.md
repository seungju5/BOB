# 밥뭇나 · 식사 안부 MVP

2026-10-07 개선. 제공된 기획 워크시트와 화이트보드 3장의 요구사항을 검증하는 **가상 데이터 기반 기능형 MVP**다. 기존 밥그릇 브랜드와 정적 HTML/CSS/ES modules 구조를 유지했다. 실물 기기나 실제 가족 간 운영 가능한 돌봄 서비스가 아니다.

## 실행

```sh
python3 -m http.server 5194 --bind 127.0.0.1 --directory dist
node tests/check.mjs
node build-portable.mjs
```

정적 버전은 `http://127.0.0.1:5194/`에서 연다. 마지막 명령은 외부 폰트·스크립트·네트워크가 필요 없는 단일 파일 `../output/apps/bapmunna-mvp.html`을 만든다. 소스를 바꾼 뒤 다시 빌드한다. 현재 대화의 로컬 미리보기는 해당 단일 파일을 `127.0.0.1:5195/bapmunna-mvp.html`에서 제공한다.

기존 Sites 프로젝트와 비공개 접근 설정을 보존한다. 등록 자체는 배포 완료가 아니다. 실제 게시 결과는 대화에서 확인한 성공 상태와 URL을 기준으로 한다.

## 5분 체험

1. 가상 시각은 2026-10-07 12:30이다. 지난 29일과 오늘 아침은 가상의 예시다.
2. `IoT 신호 체험`에서 밥솥 전력 680W를 입력한다. 사용 시작과 기기 신호는 반영되지만 직접 식사 확인은 늘지 않는다. 동일하게 680W를 다시 보내도 사용 시작은 중복 집계하지 않는다.
3. `어르신 화면`에서 점심 `오늘 외식했어요`를 누르고 체크박스로 확인한다. 가족 화면에 `외식 · 직접 확인`이 표시되고 기기 미사용 시간도 새로 관찰한다.
4. `도움이 필요해요`를 요청하고 가족 화면에서 확인한다. 어르신 화면에 확인 상태가 돌아온다. 실제 연락이나 신고는 일어나지 않는다. 요청 취소도 가능하다.
5. 가상 예시 초기화 후 시간을 2시간씩 옮겨 연속 2끼 미확인과 기기 4시간/12시간 단계를 비교한다. 기기 오프라인, 외출, 함께 거주, 공유 중지도 각각 시험한다.

## 화이트보드 요구사항 반영

|---|---|
| 기본 2주 패턴 관찰 | 7/14/21/28일 선택, 관찰 완료 일수와 단순 평균. 영양 점수나 AI 건강 예측이 아님 |
| 개인 프로필 | 거주 형태, 연령대, 평소 식사 시간대, 외식 횟수, 취사 간격, 기준 가전 |
| 연락 매개체 선택 | 밥솥 사용 습관·공동 거주 여부에 따른 설명, 기준 기기 선택. 사진 수집·자동 통화는 미구현 |
| 일·주·월 기록 | 오늘/최근 7일/최근 30일, 직접 식사 확인 그래프, 밥 지음·뚜껑 열림 비교 막대, 외식 집계 |
| 연속 2끼 미확인 | 선택한 식사 시간대의 완료된 끼니 기준. 직접 확인·외식·외출·관찰 전·연결 장애를 구분 |
| 공복시간 관련 알림 | 마지막 직접 식사 확인 이후 경과 시간. 실제 공복시간이나 생리 상태를 측정하지 않음 |
| 4시간 주의 / 12시간 재확인 | 편집 가능한 실험용 초기값. 신호나 직접 확인 없음이 지속되면 화면 내 단계 변경. 자동 신고하지 않음 |
| 시니어 외식 확인 | 큰 버튼과 확인 체크 팝업, 끼니별 중복 방지, 미래 끼니 입력 차단 |
| 도움 요청 | 요청·취소·가족 확인. 음성은 마이크 없이 예시 문구로 흐름만 시뮬레이션 |
| 관계 연결 | 전화·산책·놀러 와요 요청을 현재 탭의 가족 화면에서 확인 |
| 가전 확장 | 밥솥·냉장고·전자레인지·전기포트, 가상 전력·취사·개폐, 기기별 오프라인 |

연령·외식 횟수·취사 간격은 상담용 프로필이며, 그 값만으로 자동 위험 점수나 의료 기준을 생성하지 않는다. 거주 형태·평소 식사 시간대·기준 기기·시간 기준은 실제 데모 판정에 반영된다. 화이트보드의 분기 숫자 전체를 확정된 추천 알고리즘으로 해석하지 않았다.

## 판정 원칙

- 센서 신호와 식사 직접 확인을 구분한다. 공동 가전으로 개인 식사를 추정하지 않는다.
- 모든 확인은 자기보고다. 외식 기록은 식사 확인이고 외출 설정은 식사를 모르는 상태다.
- 주의 4시간, 가족 재확인 12시간, 연속 2끼는 회의의 실험용 값이며 의료적으로 검증된 기준이 아니다.
- 새 기기 활동·직접 식사 확인·귀가·재연결·공유 재개 이후에는 기기 미사용 시간을 새로 관찰한다.
- 기기 오프라인이면 기기 미사용·연속 미확인 추정을 중지한다. 마지막 자기보고 경과 시간은 별개의 안내다.
- 함께 거주하는 프로필에서는 개인별 기기 미사용 알림을 표시하지 않는다.
- 전력 20W 초과 전환을 데모의 사용 시작으로 집계한다. 실제 가전의 보온·대기·취사 판별을 검증한 것이 아니다. 사용량 적산이나 실제 전력요금도 제공하지 않는다.
- 신호 공백이나 도움 요청으로 자동 119 신고·전화·문자·푸시를 실행하지 않는다. 실제 응급 감시 용도로 사용하면 안 된다.
- 과거 요약은 설정을 바꿔도 다시 분류하지 않지만 현재 알림은 변경 기준으로 다시 계산한다.
- 원터치 식사 기록은 끼니별 중복 제거한다. 취사·열림 버튼은 누를 때마다 별개의 가상 신호다. 네트워크 재전송용 이벤트 ID 중복 제거는 실기기 연동 단계의 과제다.

## 개인정보·저장

가상의 최근 30일 끼니별 확인과 일별 가전 횟수, 관찰 일수, 마지막 사용·자기보고 시각, 현재 도움/관계 요청만 현재 탭의 메모리에 유지한다. 원시 이벤트 배열은 저장하지 않는다. 이 개선에서는 시간 경과 알림을 위해 마지막 사용·확인 시각과 일별 취사·열림 횟수가 추가되었다.

localStorage, sessionStorage, IndexedDB, 쿠키, 앱 백엔드로 식사 기록을 저장·전송하지 않는다. 새로고침하면 가상 예시로 돌아가며 다른 탭·기기와도 동기화하지 않는다. 실제 정보는 입력하지 않는다. 녹음·사진·영상·마이크 접근이 없다. 공유를 끄면 요약·시각·요청·관찰 일수를 모두 지우고, 재개 시 과거를 복구하거나 소급해 판단하지 않는다.

사이트 제공을 위한 호스팅 요청과 비공개 접근 제어는 별개다. 현재 코드를 실제 서비스의 개인정보·보안·동의 설계가 완료된 것으로 해석하면 안 된다.

## 검증

`node tests/check.mjs`와 앱의 `실현 가능성 점검 > 전체 동작 검사`는 같은 시나리오 검사를 수행한다. 센서/자기보고 구분, 시간 경계, 외식, 연속 미확인, 외출, 연결 장애, 공유 삭제·재개, 프로필 검증, 전력 중복, 도움 요청 등을 포함한다. 테스트 수와 통과 여부는 실행 결과로 확인한다.

다음은 아직 연결·검증되지 않았다: 실제 SmartThings/LG ThinQ/Home Assistant API와 기기별 전력 지원, 물리 센서 정확도, 로그인·권한, 영구 저장소, 가족 간 실시간 동기화, 서버 스케줄러·푸시, 실제 음성 인식, 전화·긴급 신고, 어르신 대상 사용성, 건강 개선 효과.

다음 파일럿에서는 실제 식사 기록과 신호를 비교해 오탐·누락을 측정하고, 당사자의 부담·중단권을 확인한 뒤 실제 기기 인증·통신·권한·알림을 연결한다. 테스트 통과율은 식사 감지 정확도가 아니다.
