# 밥뭇나 프로젝트 문서

작성 기준일: 2026-10-16 · 대상: Synagogue의 v0.3 Figma 기반 웹앱·로그인·개인 기록·고객관리

최신 세부 기능은 [1008 기능정의서 v1.1 반영표](worksheet-v11.md)를 함께 읽는다. 6단계 설정, 어르신 3개 버튼, 가구 단위 48/72시간 알림과 지속 전력 시뮬레이션은 이 추가 명세가 이전의 상충하는 세부 동작보다 우선한다. 실제 IoT·가족 알림·긴급 신고는 연결되지 않았다.

이 문서 묶음은 사용자가 제공한 **(9월) 문제정의 및 기획 워크시트(1006).docx**의 문제 정의, 기능 우선순위, WBS를 기준으로 작성했다. 2026-10-07 프로토타입의 현재 동작과 제품의 목표를 구분한다. 문서 초안이며, 새 제품 정책이나 실증 결과가 승인되었다는 의미는 아니다.

요청에 나온 CPS·ADT의 이전 Skill 원문은 현재 확보되지 않았다. 따라서 파일명은 유지하되 약어의 정식 풀이는 새로 확정하지 않았다. 이 묶음에서 CPS는 제품·기능 명세를, ADT는 아키텍처 결정과 데이터·타입 기록을 담는다. 원래 Skill을 확보하면 구조와 명칭을 대조한다.

## 반드시 함께 읽을 상태 구분

- **워크시트 목표:** Must 5개와 Should 1개가 MVP O로 지정되어 있다.
- **현재 구현:** 로그인 없는 가상 체험과 별도의 실제 계정·식사 기록·운영자 고객관리다. 가족 초대·역할별 요약·만료·해제 화면은 계속 같은 탭의 체험이다. 두 백엔드의 가족·기기·동의 스키마와 권한은 별도로 생성·검증했다.
- **후속 범위:** 실기기, 실제 푸시, 실제 가족 초대 전송·다른 기기 간 공유, AI 학습, 계정 전체 삭제·백업 정책. Supabase 일반 가입은 custom SMTP가 필요하다.
- **배포 상태:** 코드와 워크숍용 HTML은 GitHub에 반영되었다. 현재 비공개 저장소의 GitHub Pages는 요금제 제한으로 비활성이다. 두 버전의 프런트엔드는 기존 Firebase Hosting에서 제공하며 실제 상태는 deployment.md에 기록한다.

앱 소스는 `docs/`, 프로젝트 문서는 `documentation/`, 다운로드용 단일 HTML은 `workshop/`에 있다. 초기 설명의 보관본은 [PROTOTYPE.md](PROTOTYPE.md)에서 볼 수 있다.
