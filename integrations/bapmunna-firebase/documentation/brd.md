# BRD · 밥뭇나의 문제와 사업 요구사항

버전: 0.3 · 작성일: 2026-10-16 · 상태: 워크시트 기반 초안

근거: [WS-1·WS-2·WS-3](sources.md). 기존에 승인된 별도 BRD 원문은 확보되지 않아, 제공된 워크시트의 방향을 개발용 기준으로 정리했다.

## 문제 정의

떨어져 사는 부양 가족은 부모님과 매일 함께 식사하거나 생활 변화를 직접 관찰하기 어렵다. 전화·방문만으로는 끼니나 평소 생활의 변화가 드러나지 않아, 상태를 뒤늦게 알아차릴 수 있다는 불안을 겪는다. 워크시트는 복지 지원의 경계에 있는 어르신의 돌봄 공백을 사회적 배경으로 제시한다.

밥뭇나는 익숙한 밥솥의 사용 신호와 당사자의 직접 식사 확인을 구분해 요약하고, 가족이 안부를 물을 계기를 제공한다. 시니어에게 매번 복잡한 앱 사용을 요구하는 부담을 줄이는 것이 기술 선택의 목적이다.

## 지역과 이해관계자

| 항목 | 정의 |
| --- | --- |
| 초기 검증 지역 | 세종 |
| 확장 방향 | 대전·충청권 → 전국. 시기·규모는 미확정 |
| 주 사용자 | 원거리 부양 가족. 정보 확인과 연락 판단을 수행 |
| 참여 사용자·수혜자 | 어르신. 익숙한 생활을 유지하고 필요한 때 직접 확인·공유 선택에 참여 |
| 도입·협력 검토 대상 | 공공기관. 실제 사용 역할·권한·계약은 아직 정의되지 않음 |
| 운영 주체 | 워밍업 팀. 실제 서비스 운영 체계는 후속 설계 |

워크시트의 복지 사각지대 정의는 대상 탐색의 배경이다. 앱이 복지 자격, 건강 상태, 돌봄 필요도를 자동 판정하는 기능을 뜻하지 않는다.

## 원하는 변화와 검증 질문

| ID | 원하는 변화 | 검증할 질문 |
| --- | --- | --- |
| B-01 | 가족이 생활 변화에 대해 안부를 물을 계기를 얻는다 | 요약을 보고 다음 연락 행동을 결정하기 쉬운가? |
| B-02 | 어르신의 입력 부담을 줄인다 | 식사 체크를 이해하고 원할 때 완료할 수 있는가? |
| B-03 | 잘못된 추정을 줄인다 | 외식·외출·공동 거주·기기 장애를 결식으로 오해하지 않는가? |
| B-04 | 사생활과 통제권을 보존한다 | 수집·공유 범위와 중지 효과를 당사자가 설명할 수 있는가? |
| B-05 | 필요한 가족 구성원이 같은 요약을 본다 | 초대·역할·철회·다중 기기 상태가 일치하는가? |

현장 측정 후보는 과업 완료 여부, 상태 의미의 이해, 불필요한 연락·알림 부담, 공유 중지의 이해다. 목표 수치와 평가 표본은 현장검증 전에 팀이 확정한다. 자동 검사 58개 통과를 식사 감지 정확도나 건강 효과로 표현하지 않는다.

## MVP 범위

WS-2의 **Must/O**는 F-01 원터치 식사 체크, F-02 결식 의심 알림, F-03 알림 기준 설정, F-04 개인정보 보호, F-05 식사 패턴 리포트다. **Should/O**는 F-06 가족 초대/공유다.

F-07 식사 도장/칭찬, F-08 자동 전화는 Should/X다. F-09 음성 인식 체크, F-10 도움 요청, F-11 건강 메모는 Could/X다. 기존 프로토타입에 도움 요청 체험이 있어도 이를 근거로 원문 MVP 범위를 확대하지 않는다. 세부 추적은 [CPS](cps.md)를 따른다.

## 이번 워크숍과 운영 MVP의 차이

이번 산출물은 가상 체험 앱, 별도의 실제 로그인·식사 기록, 운영자 고객관리, GitHub 소스와 문서 세트다. Firebase와 Supabase에서 개인 기록·고객 기본정보·운영 메모를 분리했다. 운영 MVP에는 실기기 입력, 실제 푸시, 가족 초대·권한, 다른 기기 간 공유, 데이터 처리·삭제 검증이 추가로 필요하다.

AI 개인 패턴 학습은 장기 검토 항목이다. 현재 리포트는 단순 평균과 직접 확인·기기 횟수이며 영양 상태를 측정하지 않는다.

## 완료 조건과 다음 결정

- 이번 워크숍: 앱 실행, 소스·문서 추적, 가상 규칙 58개·Firebase 인증/권한 31개·Supabase 계정 권한 24개·돌봄 권한 58개와 실제 화면 흐름 검사, 변경사항 GitHub 반영을 확인한다.
- 현장 파일럿: 기기·공유·푸시·권한과 처리 정책을 먼저 검증하고 실제 사용자 평가를 수행한다.
- 미정: 공공기관 사용 범위, 기기 후보와 비용, 가족 역할·초대 방식, 운영 알림 기준, 저장·삭제 기간, 현장 일정·책임자.
- GitHub Pages는 현재 계정의 비공개 저장소에서 제한된다. 사용자가 지정한 Firebase Hosting의 `/bapmunna/`에 두 버전을 게시한다. 공개 체험과 인증이 필요한 개인 기록·고객관리를 구분한다. 저장소 공개 전환·유료 업그레이드는 하지 않는다.
