# Design · 밥 한 끼로 전하는 안부

## 2026-10-16 · 홈·기록·설정 정돈

사용자가 제공한 보호자 홈·주간 기록 화면의 따뜻한 색과 둥근 선택을 유지하면서 정보 밀도를 줄였다. 탐색은 홈·기록·더보기 세 곳으로 유지하고 설정·알림은 더보기와 상황별 진입으로 연결한다.

- 홈: 확인할 요청 → 마지막 밥솥 신호 → 오늘의 끼니 → 전화 체험. 도움 요청 확인은 실제 식사 확인이나 연락 완료로 바꾸지 않는다.
- 기록: 일·주·월, 취사·뚜껑 열림 두 수치, 누적 막대, 끼니 상태. 주간은 320px에서도 전체를 표시하고 월간만 내부에서 가로 스크롤한다. 기기 신호와 직접 확인은 색·기호·텍스트로 구분한다.
- 설정: 식사 시간 / 생활 패턴 / 안부 알림 기준의 요약을 먼저 제공한다. 네이티브 details로 한 영역을 펼치고 그 영역에서 저장한다. 외출·여행, 공유 통제는 보조 영역이며 초기화는 맨 아래에 둔다.
- 생활 패턴과 알림 폼을 분리하되 다른 영역의 기존 값을 보존한다. 추가 생활 정보와 시간 규칙은 상세 펼침 안에 유지한다. 유효하지 않은 숨은 입력은 자동으로 펼쳐 오류를 수정할 수 있게 한다.
- 320px와 큰 글씨에서는 시간 입력을 세로로 배치해 네이티브 시간 선택기가 잘리지 않게 한다. 390px 시니어 식사 확인 버튼은 첫 화면 안에 유지한다.
- 원본 토끼·도자기 이미지·노란색 브랜드를 재사용한다. 앱 모듈과 CSS에만 화면 변경을 적용했다.

## 사용자가 선택한 인터페이스

**A의 시작 화면과 초록 카디건 토끼 + C의 크고 단순한 선택 + B의 도자기 밥그릇**을 조합한다. Figma의 실제 노드·자산·스크린샷을 확인한 뒤 정적 HTML/CSS로 옮겼다. 원본 이미지·아이콘은 [assets.md](assets.md)에 추적한다.

사용자가 추가로 제공한 홈·식사 기록 스크린샷을 우선 반영한다. 크림 바탕, 짙은 갈색 글자, 노란 기기 카드, 연한 분홍 알림, 초록 직접 확인 상태를 사용한다. 본문은 휴대폰처럼 가운데 좁게 배치하고 CRM만 넓은 작업 공간을 사용한다. 시작 화면의 토끼와 브랜드, 식사 화면의 밥그릇은 유지한다. 과도한 움직임과 외부 이미지·폰트 요청을 사용하지 않는다.

## 핵심 흐름

1. 시작 → 먼저 둘러보기 → 더보기 → 식사 체크 체험 → 현재 끼니의 ‘식사했어요’ → 즉시 직접 확인 상태 → 보호자 화면 1/3에서 2/3. 이미 확인한 버튼은 비활성화해 중복 입력을 줄인다.
2. 외식 → 실제 식사했음을 체크 → 확인. 외출만으로 식사했다고 기록하지 않는다. 미래 끼니는 선택·확인을 막는다.
3. 보호자 → 밥그릇·끼니 상태 → 확인할 안부 → 읽음. 읽음은 식사 확인이나 실제 연락 완료가 아니다. 전화 버튼은 번호가 연결되지 않은 체험임을 표시한다.
4. 가족 공유 → 가상 별명과 역할 → DEMO 코드 → 같은 탭에서 수락 → 역할별 요약 → 연결 해제. 다른 기기·계정에 전송하지 않는다.
5. 공유 쉬기 → 삭제 범위 확인 → 기록·외출·요청·초대·가족 연결 삭제. 재개는 새 관찰과 새 연결이다. 생활·알림 설정은 유지한다.

## 밥그릇의 의미

| 표현 | 근거 | 해석하지 않는 것 |
| --- | --- | --- |
| 소복한 밥 | 해당 끼니를 직접 확인 | 실제 음식 종류·섭취량·영양 |
| 반 그릇 | 기기 신호만 있음 | 반 끼를 먹었다는 추정 |
| 빈 그릇 | 직접 확인·신호가 없거나 관찰 전 | 결식·위험 판정 |
| 중립 그릇 + 상태 문구 | 외출·연결 장애·공유 중지 | 생활·건강 이상 판정 |

직접 확인한 끼니는 연결 장애 중에도 직접 확인으로 유지한다. 그 외에는 오래된 기기 신호로 반 그릇을 계속 표시하지 않는다. 어르신 화면은 짧은 설명과 ‘표현 안내’로 정보를 줄이고, 보호자 화면은 상세 범례를 보여준다.

## 사용성과 접근성

- C의 선택 버튼은 최소 높이 104px, 식사 확인 버튼은 64px다. 일반 버튼도 48px를 기본으로 한다.
- 390×844에서 어르신의 식사 확인 버튼은 첫 화면 안에 위치한다. 320px에서도 전체 페이지의 가로 넘침을 만들지 않는다.
- 로컬 폰트, 충분한 글자 대비, 글씨 확대, 상태 이름·설명을 사용한다. 색만으로 상태를 전달하지 않는다.
- 본문 바로가기, 제목 초점, 네이티브 폼 검증, 대화상자 초점 가두기·Escape·원래 버튼 복귀를 제공한다.
- 입력 오류 때 값을 보존하고 오류로 초점을 옮긴다. 제출을 처리하기 전에 폼을 다시 그리지 않는다.
- 상태 토스트는 라이브 영역으로 알리되 뒤의 버튼 클릭을 가로막지 않는다. 긴 표·차트는 내부에서 스크롤한다.
- reduced motion 설정을 존중한다.

## 현장에서 검증할 것

58개 검사는 코드의 상태 규칙을 검증한다. 대상 어르신·가족의 사용성·이해·부담은 아직 현장 검증 전이다. 식사와 외식·외출을 구분하는지, 반 그릇을 실제 섭취량으로 오해하지 않는지, 공유 중지 효과를 설명할 수 있는지 관찰해야 한다.

## 실제 계정과 고객관리

노랑·크림·밥그릇의 브랜드를 계정·CRM에도 유지한다. ‘가상 데이터로 체험 중’과 ‘내 계정 · 실제 저장’을 명시적으로 구분한다. 새 계정·빈 고객 목록에 가상 기록을 넣지 않는다. 탭을 나열하지 않고 로그인 폼 아래 가입·비밀번호 찾기 링크를 두며 비밀번호를 화면 재작성 후 보관하지 않는다.

개인 기록은 오늘의 직접 확인과 저장 목록·표시 이름으로 구성한다. 삭제 전에 대상 기록을 확인한다. 고객관리는 50명씩 이어서 조회하는 기본정보, 검색·단계 필터, 선택 고객의 내부 메모로 나눈다. 로그인만으로 운영자 권한을 얻었다고 표시하지 않으며 접근 불가 화면을 제공한다. 실제 개인정보의 목적 안내와 계정/CRM 분리는 [database.md](database.md)에 연결한다.

## 이번 간소화의 구체적 적용

홈은 필요한 알림, 마지막 밥솥 신호, 오늘의 세 끼, 연락 순서다. 기기 카드 자체가 상세 화면으로 연결되며 연락은 큰 버튼 하나를 중심으로 한다. 부가 행동은 펼쳐서 본다. 존재하지 않는 도움 요청을 시각 예시를 위해 만들지 않는다.

기록은 일·주·월 선택, 취사·열림 횟수 두 카드, 금색/연한 금색 막대, 끼니 상태표 순서다. 직접 확인과 기기 신호를 색과 문구·기호로 구분한다. 상세 수치·집계는 펼침 영역에 모은다.

설정은 목적별 펼침 목록으로 줄였다. 계정은 입력 필드와 주요 제출 버튼 하나를 중심으로 하며 저장 이력·개인 설정은 필요한 때 펼친다. ‘식사했어요 · 저장’을 누르는 행위가 직접 확인이므로 중복 확인 체크박스를 요구하지 않는다. 삭제 동작에는 대상 확인을 유지한다.

`interface.css`는 기본 구성을, `refinement.css`는 좁은 화면·카드 간격·설정 목록의 세부 조정을 담당한다. 이전 Figma 시안과 최신 스크린샷의 우선순위는 sources.md에 기록한다. 최신 실제 화면 검사 범위는 test-plan.md를 따른다.


## 2026-10-16 · 시각적 관리센터

`manage/`를 크림·숲색·노란 포인트의 독립 작업 공간으로 개편했다. 상단 브랜드, 두 가지 탐색(한눈에 보기·회원 관리), 조회 시각, 네 수치 카드, 가입 추이 막대, 운영 단계 도넛, 신규 안내 카드, 회원 목록·상세 편집의 순서다. 원본 토끼와 로고를 재사용하고 외부 차트·이미지 서비스는 추가하지 않는다.

- 조회한 회원 / 최근 7일 가입 / 첫 안내 대기(신규 단계) / 이용 중(운영자 분류)을 표시한다. 실제 이용 빈도·건강 상태·응급 정도로 해석하지 않는다.
- 차트와 수치는 현재 불러온 고객 집합 기준이다. 다음 페이지가 있으면 최근 N명 기준임을 표시하고 50명씩 더 불러온다. 처음 100명에서 목록이 끊기던 제한을 제거했다.
- 가입 차트는 한국 날짜의 최근 7/30일이며 날짜를 누르면 그날 가입한 회원을 보여 준다. 30일 모바일 차트는 내부 가로 스크롤로 날짜 선택 폭을 확보한다. 도넛 범례와 수치 카드도 목록 필터로 연결한다.
- 이름·이메일 검색, 운영 단계, 가입/이용/이름 정렬, 선택 조건 초기화를 제공한다. 차트 필터는 목록 제목으로 초점을 이동한다.
- 상세 패널에 가입일·최근 계정 이용·메모 수정일을 표시한다. 단계와 메모를 함께 저장하면 수치와 차트도 갱신한다. 저장하지 않은 메모의 이동·새로고침·로그아웃을 확인하고, 저장 실패 시 입력을 보존한다.
- 처음 방문한 회원이 없으면 0과 빈 목록을 표시한다. 네트워크 오류·접근 불가·이메일 확인은 정상적인 빈 목록과 구분한다. 로그인 전에는 실제 통계나 회원을 표시하지 않는다.
- `scripts/preview-management.mjs`는 localhost에서만 합성 회원을 제공한다. 상단에 가상 데이터 표시를 붙이며, fixture와 테스트 스크립트는 배포 대상 `docs/` 밖에 둔다.

## 2026-10-16 · 더보기 정돈과 환영 모션

- 공개 이름을 밥뭇나로 복원했다. 기존 노랑·크림·원본 토끼·브랜드 조합은 유지한다.
- 더보기: 내 기록을 첫 카드로, 생활·알림 설정 / 받은 알림 / 이용 안내를 3개 행으로 노출한다. 식사 체크 / 가족 공유 / 기기 신호는 기본 접힌 ‘가상 체험 더 보기’에 둔다. 기존 7개 경로는 삭제하지 않는다.
- 시작 화면은 원본 토끼가 준비 동작→큰 점프→작은 점프→정지하는 2.8초 모션을 제공한다. 페이지 로드당 한 번 자동 재생하고, ‘다시 인사하기’로 재생한다. 이미지 디코딩과 페이지 표시를 기다리며 진입 버튼·초점을 막지 않는다.
- CSS transform/opacity만 애니메이션 처리한다. 움직임 줄이기 설정이면 JS와 CSS에서 모두 정지 상태를 유지하며 재생 버튼을 숨긴다. 발표용 MP4는 웹에서 자동 다운로드하지 않는다.

## 어르신용·보호자용 분리 · 2026-10-16

시작 화면의 두 선택을 어르신용(Senior)·보호자용(Carer) 배포 링크로 바꿨다. 어르신 홈은 한 번의 식사 확인과 외식·외출 두 보조 선택, 개인 기록 진입으로 구성한다. 기록은 큰 글씨의 간단한 목록, 더보기는 공유 통제와 안내 중심이다. 보호자는 기존 요약·차트와 알림·시간 설정·가족 초대를 유지한다. 두 화면 모두 홈·기록·더보기 세 메뉴와 눈에 보이는 체험/실제 저장 상태 줄을 사용한다. [상세 명세](editions.md).

## v1.1 화면 보강 · 2026-10-16

기존 A 시작/환영 모션·B 밥그릇·C 큰 버튼을 유지한다. 어르신 홈은 ‘외식했어요 / 놀러가요 / 도움 요청’ 3개에 집중하고 실제 개인 식사 기록은 별도 링크로 유지한다. 보호자는 6단계 초깃값 설정과 한눈에 보는 가구 기준을 사용한다. 식사 시간 상세·추가 센서 입력은 접힌 영역에 배치한다. [상세 근거](worksheet-v11.md).

## 상단 화면 전환 · 2026-10-16

정적인 역할 배지를 두 칸의 ‘어르신용 / 보호자용’ 선택으로 대체했다. 같은 크림·노랑 팔레트, 짧은 문구, 체크 표시로 현재 선택을 설명한다. 홈뿐 아니라 설정·기록·계정에서도 접근하며 로그인은 요구하지 않는다. 390×844에서 기존 어르신 3개 행동은 첫 화면 안에 유지한다. 시작 화면은 원래의 역할 선택과 토끼 인사를 그대로 제공한다.
