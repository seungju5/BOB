# 어르신용 · 보호자용

기준: 2026-10-16. `(9월) 문제정의 및 기획 워크시트(1006).docx`의 문제 정의와 기능 우선순위 표 11행을 다시 확인했다. 하나의 앱 소스와 기존 계정/DB를 사용하되, 진입 URL·홈·기록·더보기·계정 화면을 역할에 맞게 나눈다.

## 배포 주소

| 사용자 | 기본 Firebase | 별도 Supabase |

기본 `/bapmunna/`는 두 버전을 선택하는 화면이다. 각 링크를 공유하면 선택 단계를 거치지 않고 해당 홈이 열린다. 양쪽 모두 홈·기록·더보기 세 메뉴이며, 시작 화면을 제외한 모든 앱 화면 상단의 **어르신용 / 보호자용** 선택으로 즉시 바꾼다. 기존 더보기의 전환 링크도 유지한다. 버전은 화면 선택일 뿐 계정의 DB 역할이나 운영자 권한이 아니다.

## 실제 계정과 기록

어르신용 계정 화면은 기존 본인 식사 저장·조회·개별 삭제를 제공한다. 보호자용 계정 화면은 본인 회원 정보를 관리하고 실제 가족 연결 준비 상태를 안내한다. 보호자 화면에서 본인 식사를 부모님의 식사로 입력하거나 보여 주지 않도록 식사 구독과 입력 폼을 사용하지 않는다. 보호자에게 어르신의 로그인 정보 공유를 요구하지 않는다.

같은 Firebase의 두 화면은 같은 로그인 세션을 사용한다. Supabase는 별도 계정·DB이며 전환 링크도 해당 공급자 경로 안에 유지한다. 기존 이메일 확인·복구 콜백 URL은 변경하지 않는다. 브라우저에는 공급자 경로별 `senior` 또는 `carer` 선택값만 보관해 기존 콜백 복귀 화면에 사용한다. 저장소 이용이 불가능하면 안전한 기본 화면으로 열린다. 식사·이름·연락처·가상 상태는 이 선택값에 저장하지 않는다.

두 역할을 같은 탭에서 전환하면 체험 중인 가상 상태를 비교할 수 있다. 다른 탭·기기·새로고침에서는 예시로 돌아간다. 실제 가족 공유로 해석하면 안 된다. 실제 기록과 체험을 모든 화면의 상태 줄에서 구분한다.

## 구현과 배포

- `docs/editions.mjs`: 역할별 라우팅·링크·화면 선택 복귀. `docs/editions.css`: 큰 식사 버튼과 역할 표시.
- `scripts/build-editions.mjs`: 공통 HTML에서 두 진입 페이지 생성. 공유 모듈·자산을 복제하지 않는다.
- Firebase staging은 네 역할 진입 페이지에 각 공급자의 정확한 base URL을 지정한다. 기존 관리센터와 다른 사이트 경로를 보존한다.
- 단일 HTML 체험도 `#senior/report`, `#carer/report`처럼 역할을 유지한다. 실제 로그인·저장은 온라인 앱으로 안내한다.
- 로그인한 역할별 화면 검사는 `scripts/preview-editions.mjs`의 로컬 합성 계정으로 수행하며 fixture는 공개 파일에 포함하지 않는다.

## 확인한 범위

58개 도메인 시나리오, 8개 관리센터 집계 검사, 7개 버전 라우팅 검사를 통과했다. 320/390/1280px 및 큰 글씨에서 가로 넘침을 점검했다. 390×844에서 어르신 식사 확인 버튼이 첫 화면 안에 있다. 로컬 합성 계정으로 보호자 식사 조회/저장 0건, 어르신 직접 저장 1건과 화면 갱신을 확인했다. 실제 개인 계정 로그인이나 이메일 수신은 대신 수행하지 않았다.

실제 가족 간 연결·IoT 수신·푸시·계정 전체 삭제·Supabase SMTP 완료 확인은 기존 후속 범위다. 이 배포는 DB 구조나 보안 권한을 확대하지 않는다.

## 누구나 화면 전환 · 2026-10-16

로그인 여부와 관계없이 상단 두 선택을 제공한다. 현재 화면은 노란 배경·체크·`aria-current`로 구분한다. 동일 화면을 다시 눌러도 현재 페이지·입력·히스토리를 재설정하지 않는다. 다른 화면을 누르면 해당 홈으로 이동하고 URL·제목·하단 메뉴·계정 진입을 함께 갱신한다. 같은 탭의 체험 기록과 기존 인증 세션은 변경하지 않는다. 기록의 다른 기기 전송, DB 역할 승격, 가족 권한 확대는 없다. 키보드 Enter와 브라우저 뒤로/앞으로 이동을 지원하며, 버튼은 기본 44px·큰 글씨 48px 이상이다.

이번 공개 반영 대상은 Impact Series의 기본 Firebase 앱이다. KU GPA 사본과 별도 Supabase 호스팅 파일은 이번 좁은 배포에서 변경하지 않는다. 공통 소스/portable 빌드는 같은 선택 메뉴를 포함하고 공급자별 경로 유지 검사를 통과해야 한다.
