### WS-1에서 유지한 핵심

1. 초기 지역은 세종이며, 이후 대전·충청권, 전국으로 확장한다.
2. 원문 핵심 대상은 부양자·공공기관이고, 간접 수혜자는 복지 사각지대의 어르신이다. 어르신은 식사 체크 흐름의 참여 사용자이기도 하다.
3. 전화·방문이 간헐적이어서 원거리 가족이 생활 변화를 뒤늦게 알아차릴 수 있다는 문제가 출발점이다.
4. 익숙한 밥솥의 사용 패턴을 안부 연락의 계기로 활용하되, 밥솥 사용 자체로 식사나 영양 상태를 판정하지 않는다.
5. 외식·배달 등은 원터치 확인으로 보완한다. 원시 기록을 정리하고 가족에는 요약을 공유한다.
6. AI 개인 패턴 학습은 장기 방향이며 현재 구현 사실이 아니다.

워크시트의 통계 인용과 인터뷰 서술은 팀이 제공한 근거로 취급한다. 이 작업에서 원 통계와 인터뷰 모집·표본·동의 절차를 별도로 검증하지 않았다. 따라서 효과 수치, 정확도, 건강 개선, 위기 예방 실적으로 재사용하지 않는다.

## 추가 계정·DB 요청과 공개 참고

- U-9는 Ipilot의 공개 흐름을 참고한 로그인·비밀번호·별도 고객관리와 Firebase 저장 요청이었다.
- U-10: Supabase에도 같은 웹앱·DB 기능을 요청. 기존 프로젝트 `dakozsbqltciqihazzel` 사용. 이전 U-2의 생략 지시를 대체한다.
- U-11: 사용자에게 정확한 Supabase 인증 반환·이메일 확인·복구 URL을 제시하고 허용 승인을 받았다. 사용자는 공개 가입용 SMTP를 직접 설정하기로 했다.

Ipilot의 [로그인](https://ipilot.co.kr/login/), [회원가입](https://ipilot.co.kr/Register/), [개인정보 안내](https://ipilot.co.kr/privacy/)는 공개 흐름 참고용이다. 내부 고객관리·DB·비공개 화면은 확인하지 않았다. 이를 동일 스키마로 복제했다는 근거는 없다.

구현 근거는 [Firebase Auth](https://firebase.google.com/docs/auth/web/password-auth), [Firestore 접근 규칙](https://firebase.google.com/docs/firestore/security/rules-fields), [Supabase 비밀번호 인증](https://supabase.com/docs/guides/auth/passwords), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [메일 서비스](https://supabase.com/docs/guides/auth/auth-smtp), [인증 반환 URL](https://supabase.com/docs/guides/auth/redirect-urls)이다. 2026-10-16 확인. 사용자 인증·고객 데이터는 연구용으로 복제하지 않았다.
