# 산책 하트 계산

서버와 화면에서 함께 사용하는 순수 ESM 모듈입니다. React, DB, 네트워크, 기기 권한을 호출하지 않습니다. `core.d.mts`에 전체 타입이 있습니다.

## 사용

```js
import {createHeartState, advanceHearts, heartSummary} from './core.mjs';

let state = createHeartState({date: '2026-11-17', goal: 5000});
state = advanceHearts(state, {
  date: '2026-11-17',
  count: 4800,
  now: '2026-11-17T12:00:00+09:00', // 해당 걸음 합계를 읽은 시각
  cooking: true,                 // 별도로 확인된 취사/외식 소식만
});
const summary = heartSummary(state, '2026-11-17');
// percent 96, todayEarned 1, filled 3
```

`now`는 다시 화면을 열어본 시각이 아니라 해당 걸음 기록의 관측 시각입니다. 정확한 시간대가 있는 ISO 문자열, `Date` 또는 epoch milliseconds를 받습니다. 같은 날 더 오래된 기록과 동일 시각의 상충 값은 걸음 합계를 바꾸지 않습니다. 시각 없는 호출은 격리된 예시 체험에서만 사용합니다.

## 규칙

- 걸음 목표 기본값 5,000은 체험 기준이며 건강 권고가 아닙니다. 500~20,000 범위의 100단위입니다. 취사만으로 칼로리·식사량을 추정하지 않습니다.
- 오늘의 첫 걸음 관측(0 포함) 또는 확인된 취사 소식 후 목표는 고정합니다. 이후 목표 설정은 다음 날부터 적용합니다. 첫 관측 전에는 오늘 목표를 바꿀 수 있습니다.
- `count`는 증가분이 아닌 KST 하루 합계입니다. `null`은 새로 읽을 수 있는 기록이 없다는 뜻으로, 기존 확인된 수치를 지우거나 0으로 만들지 않습니다. 화면은 `observedAt`을 함께 써서 오래된 수치를 실시간으로 표현하지 않아야 합니다.
- 취사 하트는 걸음 하트와 별개입니다. 취사 정보가 없어도 걸음 단계는 채워집니다. 취사 소식은 실제 식사를 증명하지 않습니다.
- 25·50·100·200% 경계는 반올림 전의 정수 비교로 판단합니다. 비율 표시에는 소수 둘째 자리까지 내림하고, 300% 이상도 표시합니다. 주간 점수는 하루 최대 300점입니다.
- 꾸미기 보상은 하루 누적 50%=1, 100%=3, 200%=5개입니다. 새로고침·중복 전송·기록 정정으로 반복 지급하지 않습니다. 걸음 수가 줄어든 정정에서는 현재 진행·주간 점수는 낮아지지만 받은 하트를 빚으로 만들지 않습니다.
- 날짜가 뒤로 가는 입력은 닫힌 날을 다시 열지 않습니다. 최신 날짜 포함 35일만 저장하고, 자정에는 새 날짜의 진행을 시작합니다. 지갑과 구매 목록은 유지합니다.
- 7일·30일 연속 확인된 취사/외식 소식은 한복·왕관을 무료로 해제합니다. 오늘 소식이 아직 없다면 어제까지의 연속 기록을 보여주며, 다음 날에도 이어지지 않으면 연속 기록이 끊깁니다. 이것을 결식이나 영양 판정으로 사용하지 않습니다. 장기 연속 수치는 보관 기간상 최대 35일까지만 보여줍니다.
- `todayEarned`는 오늘 실제 지급한 수, `rewardTotal`은 현재 수치로 가능한 지급 기준, `monthEarned`는 이번 달 지급한 수, `balance`는 구매 후 잔액입니다.

## 꾸미기·리그

`buyHeartItem`은 소유권만 사고 `equipHeartItem`이 착용합니다. 이미 소유한 것을 다시 사거나 같은 것을 입혀도 중복 비용이 들지 않습니다. 카테고리별 한 개를 착용하며 `default`는 전체, `default-hat` 등은 해당 카테고리만 기본으로 돌립니다. `grantHeartItem`은 내부의 비현금 선물·해제용이며 임의의 클라이언트 입력에 연결하지 않습니다.

`heartLeague`는 호출자가 이미 권한·동의·지역 그룹을 확인한 회원만 받습니다. 없는 참여자를 채우지 않으며, 동점은 1·1·3 방식입니다. 현재 등급 `tier`는 서버가 전달한 0~4 값이며 점수만으로 승급을 임의 확정하지 않습니다. 반환값에는 공개 식별자·별명·지역·주간 점수·연속 소식 수·등급·순위만 있고 원시 걸음 이력이나 지갑은 없습니다. 그룹 배정·주간 승급 확정·동의 철회는 저장 계층 책임입니다.

## 저장과 검사 경계

모든 변경 함수는 입력을 수정하지 않고 새 상태를 돌려줍니다. `validateHeartState`는 버전·날짜·필드·보관 범위·소유권·잔액을 검사합니다. **검증 함수는 인증 수단이 아닙니다.** 실제 서비스는 클라이언트가 보내는 상태/잔액을 저장하지 않고 서버의 기존 상태와 승인된 기기 수치만 트랜잭션 안에서 계산해야 합니다. 동시 호출의 중복 지급 방지는 같은 문서에 대한 저장소 트랜잭션을 함께 사용해야 합니다.

```sh
node --test packages/walking-hearts/test/*.test.mjs
```

이 검사는 날짜·점수·구매 계산을 검증합니다. Health Connect/HealthKit 실측, 삼성 신호 수신, 가족 메시지 전달, 실제 푸시 도착이나 운영 배포를 증명하지 않습니다.
